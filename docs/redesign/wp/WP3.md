**Static by default (§5.9, rule 2.4.7).** The server and the hydration render are the stacked layout with every mock final (drawn, all misses shown). A layout effect then switches to sticky when it applies, so nothing paints in between and there is no hydration mismatch. A later client mount (a `<Swap>` remount after a switch) starts directly in its real layout (a module flag set at first hydration), so the anchor `<Swap>` restores is measured on the final layout. In the stacked layout with motion, step 04's mock (MockCurve draw, MockCheck misses at 120 ms) resets only if it is below the viewport at mount, then plays once at 35% in view.

**Renders.** Only `Stage` holds scroll-driven state (`active`). `Stage` and `Stack` are memoised with stable props, so across a full scroll the stage renders 4 times (first + 3 quarter crossings) and `RunStage` 0 times.

## Requests to the lead

1. **WordReveal vs `check:site`.** Any H2 that contains the word "live" fails `check:site` ("badge word as an element's whole text") because WordReveal wraps each word in its own span. I worked around it inside `run/` (deviation 5). Suggest fixing it once: either WordReveal keeps a lone "live" with its neighbour, or the check skips WordReveal's word spans.
2. **Parent re-renders on `/brands`.** With temporary counters, `RunStage` received 2 renders from above shortly after load (and in one run at scrollY ≈ 885 and 914, the sheet's arrival), on top of its own 2 mount renders. Nothing in `run/` causes them, and `Stage`/`Stack` are memoised so they do not propagate. The source is above `<Swap>`; worth a look if other sections are heavier.
3. **WP8 mocks were still stubs** while I built this. The Run mounts MockField, MockPlan, MockPay, MockCurve (`drawn` flips after mount; stacked: on entry), MockRead, MockPicks (`cards`, `shown=3`), MockTerms, MockCheck (`shown` 0 → 3). Please have WP8 confirm they fit the sticky panel (524 × 480 at 1440; 345 × 480 at 768) and the stacked mount (358 × 300 on phone; 524 × 300 at desktop under reduced motion). MockRead (header + 9 rows) and MockTerms (4 not-commits + button) are the likeliest to clip at 300px. The mounts centre in-flow children too, so the stubs sit centred.
4. **Short laptops.** With the copy as approved, creators cannot be sticky below about 700px of viewport (1366x768 screens with browser chrome are ~657px); brands holds to ~650px. It falls back to the stacked layout cleanly. If the lead wants the stage on those screens, it needs a copy decision (shorter step bodies), not a layout one.
5. **Head consistency with WP2.** I align the sub with `align-items: last baseline` on the head grid (both items join the baseline group); WP2 sets `align-self: last baseline` on the sub only, which falls back to `end`. They land within a few px of each other. `text-balance` on the H2 is mine only.
